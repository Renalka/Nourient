Nourient: System Architecture & Technical Specifications

1. Project Description

Nourient is an AI-powered nutritional intelligence platform engineered to decode complex food labels into transparent health data. The system is built on a decoupled architecture utilizing a Next.js 14 (App Router) frontend and a Python 3.11 FastAPI backend. To optimize cloud expenditure and eliminate microservice cold-start latency, the backend is architected as a high-density monolith on Google Cloud Run. A localized Nginx Reverse Proxy acts as the API Gateway within the container, routing external HTTPS traffic to 9 distinct, isolated Uvicorn ASGI processes running on local loopback addresses (127.0.0.1).

The intelligence layer relies on a multimodal computer vision pipeline (Google Gemini API) for OCR and JSON schema enforcement, a custom Scikit-learn Decision Tree Regressor for non-linear nutritional scoring, and a 384-dimensional semantic search engine powered by SentenceTransformers (all-MiniLM-L6-v2) and a Pinecone Vector Database.

2. Project Use Case

The food industry leverages deceptive marketing (e.g., claiming "Zero Sugar") and complex chemical aliases (e.g., masking sugar as Maltodextrin or Dextrose) to bypass traditional consumer scrutiny. Traditional lexical databases fail to connect these aliases. Nourient solves this via Dense Vector Similarity Search—mapping chemical structures and aliases into semantic space—and a TrueLabel Auditor that programmatically cross-references front-of-package marketing OCR against back-of-package chemical realities. It shifts nutritional analysis from isolated, single-product tracking to calculating the Cumulative Dietary Load across an entire grocery basket.

3. Technical Architecture Diagram

  • Client Tier: Next.js 14 (React Server Components + Client Hooks) → Routed via Cloudflare DNS (Strict SSL)
  • API Gateway Tier: Nginx Reverse Proxy (Exposed on Cloud Run $PORT, typically 8080)
  • Backend Monolith Tier (Google Cloud Run / Python FastAPI):
    • Orchestrator (127.0.0.1:8003) — Main ingress router; handles payload validation and async task delegation.
    • Extraction Engine (127.0.0.1:8000) — Constructs Base64 image payloads for the Google Gemini Multimodal API, enforcing strict JSON output schemas for macro/micro parsing.
    • Scoring ML Engine (127.0.0.1:8001) — Loads a serialized Scikit-learn DecisionTreeRegressor to calculate the proprietary Metabolic Fit Score using an ensemble of FSA-NPS algorithms and NOVA classification logic.
    • TrueLabel Auditor (127.0.0.1:8002) — Orchestrates multi-image LLM prompts to detect contradictions between marketing and ingredients.
    • Ingredient Detective (127.0.0.1:8004) — Generates query embeddings using all-MiniLM-L6-v2 to query Pinecone via gRPC.
    • BioContext Profile (127.0.0.1:8005) — Manages user personalization weights (e.g., scaling sodium penalties for hypertension profiles).
    • Alternatives Engine (127.0.0.1:8006) — Executes K-Nearest Neighbor (KNN) vector searches with metadata pre-filtering to find healthier product substitutions.
    • Smart Basket Logic (127.0.0.1:8007) — Executes MapReduce-style aggregation arrays to calculate cumulative payload toxicity based on frequency multipliers.
    • Nutrition DB (127.0.0.1:8008) — Provides static lookup endpoints for standard additives.
  • Data Tier:
    • Firebase Auth: Issues JWTs for stateless session verification.
    • Firestore (NoSQL): Manages document-oriented storage for user scan histories and BioContext profiles.
    • Pinecone Vector DB: Handles high-throughput cosine-similarity queries for product matching.

4. Page-by-Page Feature & Technical Specifications

4.1. The Dashboard (/dashboard)

The Dashboard acts as the primary data visualization hub, utilizing React hooks (useEffect, useState) bound to Firebase Firestore snapshot listeners for real-time UI hydration.

  • BioContext Mutation Modal: A state-driven UI component that updates the user's biological profile document in Firestore. Changing this state (e.g., to "Gut Health") alters the penalty weights applied to certain chemical additives in the Scoring ML Engine.
  • Chronological Scan Feed: Renders paginated, cached NoSQL documents.
    • Data Parsing: Maps over the JSON array of ingredients extracted from previous sessions.
    • Metric - Nutri-Score (primaryLabel): Displays the computed FSA-NPS (Food Standards Agency Nutrient Profiling System) score. Dynamically re-renders as a "Decept" badge if the backend Auditor microservice flagged a boolean contradiction_found flag.
    • Metric - NOVA Score (secondaryLabel): Displays the degree of food processing (1-4 scale, normalized to a 100-point UI scale).

4.2. The Multi-Mode Scanner (/scanner)

This route manages complex state handling for device cameras, file uploads, and Base64 encoding before transmitting payloads to the Orchestrator API.

  • Mode 1: Ingredients Analysis
    • Data Flow: Image → Base64 → Orchestrator → Extraction Engine (Gemini) → JSON Schema validation → Scoring Engine.
    • ML Scoring Pipeline: The extracted nutritional payload is vectorized and passed to the DecisionTreeRegressor. The model evaluates features (Sugar, Saturated Fat, Sodium, Fiber, Protein) against penalty thresholds to output the Metabolic Fit Score.
    • Additive Risk Table: Renders a mapped array of chemicals. The backend cross-references each chemical against EFSA (European Food Safety Authority) datasets to append categorical strings (risk_level, source).
  • Mode 2: Claims Verifier (TrueLabel Auditor)
    • Data Flow: Concatenates two Base64 image payloads (Front Marketing + Back Ingredients) into a single multimodal prompt.
    • Execution: The LLM is instructed via a strict system prompt to act as an FDA regulatory auditor, outputting a JSON object containing a boolean is_deceptive flag and a reasoning string if contradictions are found.

4.3. Healthy Alternatives (/alternatives)

A high-performance recommendation interface relying on Dense Vector Search.

  • Search Thresholds Engine: The UI allows users to inject constraints (e.g., max_sugar_g). These are passed as metadata filters ($lte) to the Pinecone query object, narrowing the search space before distance calculations.
  • Recommendation Cards:
    • Metric - betterment_score: A normalized integer (0-100) calculated by taking the inverse Euclidean distance between the scanned product's vector and the alternative's vector, weighted by improvements in the Metabolic Fit Score. Rendered via an SVG circular progress bar.
    • Delta Array: The backend computes the delta between the original product's macros and the alternative's macros, generating an array of strings (e.g., "50% Less Sugar") mapped to UI pill badges.

4.4. Smart Grocery Basket (/basket)

This page handles heavy client-side state manipulation to calculate Cumulative Dietary Loads without hammering the API.

  • Metric - Clinical Habit Score: An aggregated algorithm. It takes the baseline FSA-NPS score of the basket and applies a frequency multiplier array based on user input. (e.g., Daily = 1.0, Weekly = 0.14, Occasional = 0.03).
  • Metric - UPF Proportion: Iterates through the basketItems array, summing items with a NOVA classification of 4 (Ultra-Processed), divided by array length.
  • Behavioral Matrix: A stateful list component. Adjusting a toggle (e.g., from Weekly to Daily) triggers a React useMemo recalculation of the entire basket's toxicity threshold, instantly updating the UI without a network request.

4.5. The Ingredient Dictionary (/dictionary)

A semantic search interface designed to bypass the limitations of fuzzy string matching (e.g., Levenshtein distance) when dealing with chemical aliases.

  • Vectorization Process: The user's query string is sent to the Detective microservice, which passes it through the SentenceTransformer('all-MiniLM-L6-v2') model. This outputs a 384-dimensional dense vector representation of the string.
  • Semantic Alias Grouping: The vector is queried against the Pinecone index using Cosine Similarity. Because vectors capture semantic meaning, querying "Sugar" will return highly similar vectors for Dextrose, Maltodextrin, and High Fructose Corn Syrup, exposing industry obfuscation seamlessly.
  • Result Hydration: The matched vectors return metadata payloads containing the chemical's E-number, natural language biological impact, and integer risk severity.
